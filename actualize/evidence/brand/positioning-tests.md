# Positioning tests
Positioning (decided, D4): For technical founders and small teams who build with coding agents and now have to launch, Product Actualizer is evidence-gated product completion: one graded model of what is true, specialist work ordered against it, and a gate that can say no. Instead of agent chat plus notes, a spec toolkit for the code, and separate tools for brand, site and film. Not for people who want an agent to ship without an owner reading the verdict.

1. Negation. "Our source of truth is whatever the spec says." Spec Kit, Kiro and OpenSpec plausibly say this (S1, S14), so "spec" is not our difference. "Every artifact cites graded claims and goes stale when they change" is not claimed by any source above; marked PROPOSED (C36) because absence in one search is not proof.
2. Alternative. Agent chat + CLAUDE.md/AGENTS.md notes (S7, S8), spec toolkits for code (S1), app builders (S5), a studio for handoff (S12). All sourced.
3. Tagline "says who?". "Finish the product. Show the evidence." Finish: gate and waves (C5, C6). Show the evidence: grades and sources (C2, C3). It does not say "prove": the model grades evidence; it does not guarantee correctness.
4. Not-for: autonomous-by-default buyers (S9); anyone needing a hosted service (the product is local files, a CLI and an optional local cockpit); anyone needing code-correctness guarantees (it does not write your tests).
5. Spoken test, mark reproduction at 16 px: not run here; assigned to fidelity-qa and U8.
