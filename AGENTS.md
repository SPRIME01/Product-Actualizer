# Product actualizer

Agent skills that move an incomplete product toward a coherent launch through one shared Product Model.
The skills are plain Markdown, YAML, and JSON. The hooks and the cockpit run on Bun >= 1.4 (no Node).

- Entry point: `skills/actualize-product/SKILL.md`. Always loaded with it: `product-model/SCHEMA.md`.
- Lenses are `skills/<name>/SKILL.md` (60-100 lines; sections: Reads from the model, Distinctions, Failure modes, Check, Writes to proposals).
  Longer detail goes in that skill's `references/`, loaded only when the lens says so.
- Lens frontmatter: `reads` (model fields it may use), `needs` (lenses whose output must exist first), `executes_with` (existing skills used as the execution layer when installed).
- Only the router edits a product's `product-model.md`; lenses write to `proposals.md`.
- `python3 tests/check.py` verifies size limits, structure, the fixture model against the schema, and artifact staleness. The worked examples are `tests/walkthrough/` (Loam, software and a sensor) and `tests/walkthrough-mote/` (a hardware and physical-AI product); a hardware walkthrough keeps its evidence package under `evidence/recon-physical/hardware/`.
- Donor material is recorded in `PROVENANCE.md`; reference clones go in `.tmp/ref/` and are deleted after use.
- `cockpit/` is the optional interactive cockpit (protocol in `cockpit/protocol/`, reducer and server in `cockpit/server/`, UI in `cockpit/web/`). It never owns state: the run directory is authoritative; its SQLite holds a disposable projection and, separately, durable cockpit-owned `control_*` state (work requests, bindings, declared budgets, reviews) that never settles Product Model truth; and every owner gesture that bears on the process is an inbox entry the router handles. The agent drives it through `skills/cockpit/` (a `kind: tool` skill, not a lens). `bun test` includes browser tests (system Chrome via `playwright-core`). Do not add UI code paths the agent could reach other than the typed vocabulary. `cockpit/server/world.ts` is the read-only world debugger (`actualize world why|impact|diff|timeline|counterfactual|reach|replay`): functions of the run files, never a store; a historical world or a candidate is not the current world, and nothing there settles anything (see `docs/world-debugger.md`). `cockpit/server/case.ts` derives the Case (destination, deviation, the affordance field, settlement) the same way: a Case, a purpose, a score, or a decision state is never stored, the primary move is guidance and never authority, and `settlementReachable` is not `shouldSettleNow` (see `docs/case-navigation.md`; residuals in `.agents/DEBT.md`). The Workbench (`screens.ts`) and Work Terminal (`terminal.ts`) are deterministic: no LLM interprets the terminal, a typed request is `queued` until an executor acknowledges it, and the agent can never accept its own work (see `docs/workbench.md`).
- `hooks/` enforces the process across Claude Code, Codex, Cline, OpenCode, and Pi/Prime (`bun hooks/install.mjs`). Engine rules live in `hooks/src/engine.mjs`; `bun test` replays both walkthroughs (Loam and the physical-AI Mote).
